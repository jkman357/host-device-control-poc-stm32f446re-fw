# STM32F446RE Host–Device Control PoC Firmware

Bare-metal, event-driven firmware for the **NUCLEO-F446RE**. The PC communicates through the board's ST-LINK Virtual COM Port, which is connected to STM32 USART2 on PA2/PA3.

## Scope

- No RTOS and no heap allocation
- Event-driven superloop
- USART2 at 115200, 8-N-1
- Interrupt-driven RX/TX ring buffers
- TIM6-generated 5 ms application event
- `PING`, `GET_DEVICE_INFO`, `START_STREAM`, and `STOP_STREAM` commands
- 200 Hz signed 16-bit sine-wave telemetry
- Framing, sequence number, and CRC-16/CCITT-FALSE

## STM32CubeIDE import and build

Use a **fresh import**. Do not reuse the `Debug` folder generated by v0.1.0.

1. Close the old project in STM32CubeIDE and remove it from the workspace without deleting the repository files.
2. Delete any existing `Debug/` and `Release/` folders from the repository.
3. Replace the repository working tree with this package while keeping `.git/`.
4. In STM32CubeIDE select **File → Import → Existing Projects into Workspace**.
5. Select the repository root and import `host-device-control-poc-stm32f446re-fw`.
6. Select **Project → Clean**, then build the **Debug** configuration.

The project metadata is based on the original CubeIDE-generated NUCLEO-F446RE target definition. `Debug/` and `Release/` are generated locally and are not part of the source package.

## Important implementation note

This PoC uses a small register-level platform layer and therefore does **not** include STM32 HAL/CMSIS source packages or a CubeMX `.ioc` file. Do not run CubeMX code generation on this project. A future HAL/LL migration should replace only `Platform/` and `Transport/`; `App/` and `Protocol/` should remain independent.

## CubeIDE linker diagnostics

The project defines `_close`, `_lseek`, `_read`, and `_write` as explicit unsupported bare-metal syscall stubs. This prevents STM32CubeIDE/newlib-nano from reporting the four `not implemented and will always fail` diagnostics when the application does not use POSIX file I/O.

The linker script declares two loadable program headers: executable/read-only Flash and initialized read/write RAM data. Zero-initialized `.bss` and reserved heap/stack sections are `NOLOAD` sections assigned to `:NONE`, because they must occupy RAM addresses but must not belong to any ELF `PT_LOAD` segment. This prevents both the GNU linker `LOAD segment with RWX permissions` warning and the `._user_heap_stack lma ... adjusted ...` diagnostic.

## Runtime flow

```text
TIM6 IRQ ──> pending 5 ms tick count ─┐
USART2 IRQ ──> RX/TX ring buffers ────┼─> main-context event processing
UART error ──> event flag ────────────┘
```

Interrupt handlers only move bytes, acknowledge hardware, update bounded counters, and post events. Parsing, command handling, state transitions, telemetry construction, and sine generation execute in the main context.
